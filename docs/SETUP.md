# Setup & deployment

ROYALWEB AUTOPILOT runs on Node 22+ with no external database or cloud dependency. Everything persistent
lives under `data/`.

## 1. Requirements

- Node.js **22.5+** (uses the built-in `node:sqlite`). Node 22 LTS recommended.
- ~500 MB disk for the app plus uploads.
- Optional: `ffmpeg` for YouTube Shorts rendering.
- A public HTTPS URL for OAuth callbacks and platforms that require image URLs.

## 2. Install

```bash
npm install
cp .env.example .env.local
```

## 3. Environment

Minimum viable configuration: none. For production set at least:

```env
PUBLIC_BASE_URL=https://autopilot.yourdomain.com
ROYALWEB_ENCRYPTION_KEY=<openssl rand -base64 32>
ROYALWEB_ADMIN_EMAIL=you@yourdomain.com
ROYALWEB_ADMIN_PASSWORD=<strong password, 12+ chars>
ROYALWEB_WORKER_SECRET=<openssl rand -hex 32>
```

`ROYALWEB_ENCRYPTION_KEY` protects every platform credential. **Back it up and keep it stable** — losing it
means reconnecting all accounts. If unset, a key file is generated at `data/.keys/master.key` (0600).

## 4. Database

Migrations run automatically on first start. Manual control:

```bash
npm run db:migrate     # apply pending migrations, print table counts
npm run db:reset       # delete data/royalweb.db (destructive)
npm run db:reset && npm run dev
```

Seed data:
- 25 platform rows are inserted/synchronised on every boot (`src/lib/bootstrap.ts`).
- The first admin is created from env if no user exists; otherwise `/login` shows a first-run form.

## 5. Run

```bash
npm run dev            # development, binds 0.0.0.0:3000
npm run build && npm start   # production
```

The publishing worker starts inside the server process (`instrumentation.ts`, 20s tick). For serverless or
split deployments, run the standalone worker instead:

```bash
ROYALWEB_BASE_URL=https://autopilot.yourdomain.com \
ROYALWEB_WORKER_SECRET=… \
npm run worker
```

…or call `POST /api/worker/tick` with header `x-worker-secret` from your platform's cron (every 1–5 min is
sufficient). Set `ROYALWEB_DISABLE_WORKER=1` on web instances when using an external worker.

## 6. Connect the AI provider (optional)

Dashboard → **Settings → AI**:
- choose a provider (OpenAI, Anthropic, Gemini, Groq, OpenRouter, Ollama, or a custom OpenAI-compatible base
  URL),
- paste the API key (stored AES-256-GCM encrypted),
- press **Test** — this performs a real request and reports the model and latency.

Without a provider the app still works: content is generated by the built-in template engine and labelled
"Template" in the campaign view. Poster text is only read when a vision-capable model is configured.

## 7. Register OAuth applications

Add client IDs/secrets in **Settings → Integrations** (or the matching environment variables). Register the
redirect URI `https://YOUR_DOMAIN/api/oauth/<provider>/callback`.

| Provider | Where to create the app | Scopes / notes |
|---|---|---|
| Google | Google Cloud Console → APIs & Services → Credentials | Enable Blogger API v3, YouTube Data API v3, Business Profile APIs as needed. Scopes are requested per platform. |
| Pinterest | developers.pinterest.com → My Apps | Needs app review for standard access before pins can be created. |
| LinkedIn | developer.linkedin.com → My Apps | `openid profile w_member_social`; Community Management API for company pages. |
| X | developer.x.com → Projects & Apps | OAuth 2.0 PKCE, read+write; a **paid API tier is required to post**. |
| Slack | api.slack.com/apps → OAuth & Permissions | Bot scopes `chat:write files:write channels:read`. |
| Tumblr | tumblr.com/oauth/apps | OAuth2, scopes `basic write offline_access`. |

Non-OAuth platforms (WordPress, Telegram, Discord, Bluesky, Mastodon, DEV.to, Hashnode, Ghost, Flickr,
Matrix) connect with their own app passwords/tokens in **Connected Accounts → Connect**.

## 7b. Connecting platforms fast

Open **Connected Accounts**. The quick-connect wizard at the top of the page groups the 25 platforms into
*Fastest to connect*, *OAuth / approval* and *Manual*. Each row has a **Get key ↗** deep link to the page that
issues the credential, a one-line instruction, a Paste button per field and a single **Save & verify all**
action for everything you filled in. Empty platforms are simply inactive — no warnings. Full details and the
bulk API: [QUICK_CONNECT.md](QUICK_CONNECT.md).

## 8. Public media URLs

Several platforms need a reachable image URL instead of a file upload (Blogger, Ghost cover, DEV.to cover,
Google Business posts, Hashnode cover). Set `PUBLIC_BASE_URL` so the server can mint signed URLs of the form:

```
PUBLIC_BASE_URL/api/public/media/<mediaId>?preset=<platform>&sig=<hmac>
```

The signature is derived from the encryption key, so URLs are unguessable and expire with key rotation.
Without it, those platforms publish text only and the publishing log records why.

## 9. YouTube Shorts (optional)

Install ffmpeg:

```bash
# Debian/Ubuntu
sudo apt-get install -y ffmpeg
# macOS
brew install ffmpeg
```

or set `FFMPEG_PATH=/path/to/ffmpeg`. Alternatively, upload a vertical MP4 (15–60s) to the campaign; the
adapter uses that file directly.

## 10. Reverse proxy (example)

```nginx
server {
  listen 443 ssl http2;
  server_name autopilot.yourdomain.com;
  client_max_body_size 220M;   # videos

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

## 11. Backups

Back up `data/royalweb.db` (plus `-wal`), `data/uploads/` and the encryption key together. A database without
its key cannot decrypt platform credentials.

```bash
sqlite3 data/royalweb.db ".backup 'backup-$(date +%F).db'"
tar -czf uploads-$(date +%F).tar.gz data/uploads
```

## 12. Verifying the deployment

```bash
curl -s https://YOUR_DOMAIN/api/health | jq
# { "ok": true, "data": { "status": "ok", "platforms": 25, ... } }
```

Then run the acceptance suite against it:

```bash
TEST_BASE_URL=https://YOUR_DOMAIN \
TEST_EMAIL=you@yourdomain.com \
TEST_PASSWORD='…' \
npm run acceptance
```

## 13. Updating

```bash
git pull
npm install
npm run build && npm start
```

Migrations are additive and idempotent. Take a backup before updating.

## 14. Moving to PostgreSQL/Supabase

The data layer is isolated in `src/lib/db/index.ts` (`all/get/run/tx`) and the schema is standard SQL. To
move: translate the migrations in `src/lib/db/migrations.ts` (TEXT/INTEGER → appropriate types), replace the
query helpers with a `pg`/Supabase client, and keep the same function signatures. Uploads can be moved to
Supabase Storage by swapping `src/lib/media/storage.ts`.
